📌 Présentation du Projet

Ce projet met en place une architecture serverless hautement disponible sur AWS pour ingérer en temps réel les flux de données envoyés par des milliers de capteurs IoT industriels via des requêtes HTTP POST.

L'ensemble de l'infrastructure est automatisée avec AWS CloudFormation (Infrastructure as Code). Les données brutes sont stockées dans un Data Lake sur Amazon S3 et les métriques agrégées dans un Feature Store analytique sur Amazon DynamoDB, le tout traité à la volée par une fonction AWS Lambda (Python 3.11).

La présente documentation technique est quant à elle hébergée dans un bucket S3 privé, rendu accessible de manière sécurisée via une distribution Amazon CloudFront avec Origin Access Control (OAC).

⚙️ Flux de Traitement des Données

  1. Le capteur IoT envoie une requête HTTP POST contenant un payload JSON vers l'URL CloudFront d'ingestion.
  2. CloudFront route la requête vers l'API Gateway en appliquant les règles de cache et de sécurité réseau.
  3. API Gateway (route POST /ingest) déclenche la fonction Lambda via une intégration proxy.
  4. La fonction Lambda parse et valide le JSON, puis sauvegarde le payload brut dans S3 avec un partitionnement temporel raw-zone/year=YYYY/month=MM/.
  5. Lambda calcule en temps réel la température moyenne et le nombre d'enregistrements en statut ERROR.
  6. Un rapport condensé est inséré dans la table DynamoDB (request_id, timestamp, chemin S3, métriques).
  7. Lambda retourne une réponse HTTP 201 Created au capteur.

🗂️ Stratégie de Partitionnement S3

Chaque payload reçu est stocké dans le bucket Data Lake selon la structure de partitionnement temporel suivante, optimisée pour les requêtes analytiques (compatible AWS Athena / Glue) : 

# Structure de clé S3
akougblenou-iot-data-lake/
└── raw-zone/
    └── year=2026/
        └── month=06/
            └── <uuid-request-id>.json

🔒 Sécurité — Origin Access Control (OAC)

❌ Accès S3 direct bloqué

Le bucket akougblenou-tech-doc a le blocage d'accès public activé. Toute tentative d'accès via l'URL S3 directe retourne une erreur 403 Access Denied.

✅ Accès via CloudFront OAC

Seule la distribution CloudFront est autorisée à lire le bucket, grâce à un Origin Access Control (OAC) signé avec SigV4. L'utilisateur final n'accède jamais à S3 directement.

🖥️ Déploiement via AWS CLI

Déploiement de la pile CloudFormation

aws cloudformation deploy \
  --template-file template.yaml \
  --stack-name akougblenou-iot-pipeline \
  --capabilities CAPABILITY_NAMED_IAM \
  --region eu-west-3

Upload de ce fichier index.html dans S3

aws s3 cp index.html \
  s3://akougblenou-tech-doc/index.html \
  --region eu-west-3

Mise à jour du code Lambda

zip function.zip index.py
aws lambda update-function-code \
  --function-name akougblenou-iot-ingestion \
  --zip-file fileb://function.zip \
  --region eu-west-3
